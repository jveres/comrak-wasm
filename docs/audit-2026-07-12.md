# Performance and architecture audit

This audit records the repository state on 2026-07-12 after the dependency,
TypeScript, Comrak, API, and playground updates. Measurements use release Wasm
on an Apple M2 with Node.js 22.21.1 unless noted otherwise.

## Outcome

The audit fixed every identified high-severity correctness and safety issue.
The remaining work consists of medium-priority allocation, API amortization,
bundle-loading, and module-boundary improvements.

## Measurements

The benchmark harness uses seven samples after warmup and reports median
latency. Run it with `pnpm run bench`.

| Measure | Before | After | Change |
| --- | ---: | ---: | ---: |
| Heal, 256 KiB plain | 10.98 ms | 1.10 ms | 10.0x faster |
| Heal throughput | about 24 MB/s | 227.93 MiB/s | about 9.5x |
| Heal, split input | 3.78 ms | 1.10 ms | 3.5x faster |
| Split throughput | about 69 MB/s | 228.17 MiB/s | about 3.3x |
| Playground JavaScript | 9.39 MiB | 1.21 MB | about 87% smaller |
| Playground JS chunks | 347 | 1 | 346 fewer |
| Wasm artifact | 963.55 KB | 995.66 KB | 3.3% larger |

The Wasm increase comes from Comrak's attribute AST support, Unicode terminal
width handling, stricter validation, and callback fallbacks. The playground's
JavaScript reduction comes from explicit Shiki language and theme imports.

The initial TypeScript migration comparison, before widening the checked source
set, improved from 0.55 seconds and 137,593 KB on TypeScript 6 to 0.064 seconds
and 74,482 KB on TypeScript 7. The final strict configuration checks 353 files,
including every example, in about 0.33 seconds and 201 MB.

## Fixed findings

The implementation now addresses the following audit findings.

- Deep text and ANSI input returns a controlled `RangeError` instead of
  overflowing the JavaScript stack.
- ANSI width calculation ignores CSI and OSC sequences and measures Unicode
  terminal cells. Hidden hyperlink URLs can no longer amplify table padding.
- Threaded Wasm builds fail at compile time until the allocator and callback
  bridge support atomics safely.
- Block directives retain their content in HTML, text, and ANSI output.
- Footnotes render directly into their aggregate buffer, and unused list state
  no longer allocates or performs push/pop work.
- `healMarkdown` has a plain-text fast path, correct fence lengths and marker
  types, bounded fixed-point handling, and a seeded property test for
  idempotence.
- Malformed options and ANSI themes throw clear JavaScript errors instead of
  silently replacing valid settings with defaults.
- Syntax and heading adapters are reusable across calls. The typed root wrapper
  clones callback handles while hiding generated owned-entry helpers.
- The ineffective XML plugin path is now a zero-overhead deprecated alias to
  `mdToXml`; the dead Wasm export was removed.
- Throwing and non-string callbacks fall back to escaped, structurally valid
  output.
- Shiki fallback code and attributes are HTML-escaped. Formatter attributes
  such as source positions and code metadata are preserved.
- Package exports expose one typed root API and an explicit Wasm asset subpath.
  Packed consumers cannot accidentally import the generated, `any`-heavy
  declaration surface.
- The pnpm and Cargo lockfiles are tracked, and the Shiki example belongs to the
  root pnpm workspace.
- Strict TypeScript checking now includes JavaScript, CLI, playground, and
  Shiki example sources.
- The playground uses fine-grained Shiki imports and debounces input rendering.
  `pnpm dev` serves the app without launching a browser.

## Comrak API bridge

The resolved and registry-current release is Comrak 0.54.0. The bridge covers
the release's added math, alert, source-position, directive, and attribute
settings:

- `mathLatex` and `blockDirective`
- `sourceposChars`
- semantic or specific `alertStyle`
- heading, fenced-code, inline-code, and link attribute parsing

The deprecated `headerIds` property remains a compatibility alias for
`headerIdPrefix`; the current property wins when callers provide both.

Comrak stores parsed attributes on AST nodes, but its stock HTML, CommonMark,
and XML formatters do not expose them. This package has no JavaScript AST API,
so the four attribute flags intentionally consume the source syntax without
returning the metadata. Full support requires a future typed AST or custom
formatter API.

The playground fixture lives in
`examples/playground/sample.md`. A compile-time inventory covers all 35 public
extension properties, all nine parse properties, and all 18 render properties.
Separate toolbar modes demonstrate the mutually exclusive wikilink orders and
raw HTML omit, escape, and trusted behavior.

Phoenix HEEx nodes are template syntax, not ordinary raw HTML. Upstream Comrak
passes them through even when raw HTML is omitted or escaped. Applications must
enable `phoenixHeex` only for trusted templates.

## Remaining findings

These items remain intentionally deferred because each requires a larger API or
algorithm change.

- **Medium — text tables.** A 1,000 by 10 table took 122 ms and 97 Wasm
  pages. Benchmark a two-pass width and direct-render design.
- **Medium — option setup.** A populated tiny HTML call took 6.04 us versus
  0.88 us without options. Consider a prepared-options handle.
- **Medium — JavaScript callbacks.** Boundary cost was about 0.87 us per fence
  and 1.55 us per heading. Consider batch-oriented adapters.
- **Medium — initial bundle.** The optimized playground still emits a 1.21 MB
  chunk. Lazy-load KaTeX and highlighting when needed.
- **Medium — Rust modules.** `src/lib.rs` still combines DTOs, adapters, and
  exports. Split options and plugin bridges from the Wasm facade.
- **Low — walker evolution.** One inline wildcard match can hide a future
  Comrak leaf variant. Share exhaustive inline handling.
