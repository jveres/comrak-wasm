# Clean-code and performance audit

This follow-up audit records the repository state on 2026-07-14. It closes the
practical leftovers from the
[2026-07-12 audit](audit-2026-07-12.md), rechecks adjacent correctness and
resource-lifecycle paths, and expands the repeatable benchmark coverage.
Measurements use release Wasm on an Apple M2 with Node.js 22.21.1.

## Outcome

The round fixes the table-retention, repeated-option, initial-bundle,
module-boundary, and walker-evolution findings from the previous audit. It also
finds and fixes quadratic healer inputs, terminal escape injection, concurrent
initialization races, renderer lifecycle leaks, and several text-rendering edge
cases.

Synchronous JavaScript plugin callbacks remain an explicit architectural cost.
The existing callback API must return output for each node while Comrak formats
the document, so removing the boundary crossing requires a separate batched API
with different callback semantics.

the initial JavaScript path; each loads only when its feature is enabled.

914,189 bytes. Controlled tiny-render measurements found no material latency
regression from the optimization.

## Previous audit leftovers

The previous findings now have the following dispositions.

- **Text tables:** table layout uses a two-pass traversal with reusable scratch
  storage. It retains cell widths, not every rendered cell string, and renders
  cells directly into the final output on the second pass. End-to-end time is
  unchanged because parsing, AST storage, and final output dominate this case;
  fresh Wasm growth falls by four pages. Decorative column widths are capped at
  256 cells so a single wide cell cannot force quadratic padding; content is
  preserved and may overflow the border.
- **Option setup:** `PreparedOptions` deserializes and maps configuration once,
  then exposes stock and plugin renderers. `PreparedCodefenceRenderers` avoids
  repeated registry enumeration and validation, while `PreparedAnsiTheme`
  avoids repeated theme deserialization, allocation, and default merging.
- **JavaScript callbacks:** fixed-arity callback calls avoid one temporary
  argument array in code-fence renderers. Per-node boundary cost remains about
  0.95 us per highlighted fence and 1.55 us per heading in the synthetic
  benchmark. A batch API remains a separately designed feature.
- **Initial bundle:** Shiki and KaTeX use dynamic imports and are disabled by
  default. The initial JavaScript entry falls from 1.21 MB to 29.92 kB.
- **Rust modules:** option DTOs and plugin bridges moved from `src/lib.rs` into
  `src/options.rs` and `src/plugins.rs`; the facade now focuses on exports and
  shared rendering entry points.
- **Walker evolution:** inline rendering is shared and exhaustive. New Comrak
  block variants cannot silently fall through the old wildcard branch.

## Additional fixes

The wider audit also addresses newly identified issues.

- Fence detection in `healMarkdown` checks only the four relevant preceding
  bytes instead of rescanning to the start of the line for every marker.
- Bracket healing compacts unmatched markers in place instead of repeatedly
  draining and shifting the remaining string. Position-only tracking halves
  the adversarial 1 MiB high-water growth measured before this cleanup.
- Incomplete HTML suffixes are removed in one linear scan, including more than
  eight nested incomplete tag starts, while healer output remains idempotent.
- Text and ANSI output preserve escaped-tag markers, escaped-tag content, and
  wikilink titles. The match over inline node variants is exhaustive.
- Terminal width uses Unicode string width for emoji ZWJ sequences, flags, and
  variation selectors as well as combining marks and ANSI control sequences.
- Unknown escape bytes followed by multibyte text no longer move the width
  scanner onto an invalid UTF-8 boundary.
- ANSI output removes control characters originating in Markdown text, code,
  URLs, and titles; control-character table shadows are rejected.
  Formatter-generated styles and trusted theme escapes remain intact.
  Printable literals use a byte-scan fast path.
- Table shadows must be empty or one non-control Unicode scalar value,
  preventing a caller-supplied string from being repeated across the full
  table width.
- CRLF frontmatter extraction removes complete line endings without leaking a
  carriage return into the returned content.
- Concurrent default initialization calls share one promise and one Wasm
  instance. `initSync` reports a deterministic error during an asynchronous
  initialization race, and failed initialization can be retried.
- Invalid code-fence renderer maps and URL rewriters throw targeted
  `TypeError`s instead of being ignored silently.
- Public adapter declarations include `Symbol.dispose`, and the playground
  frees replaced adapters and resources on teardown without breaking the
  browser back-forward cache.
- The playground caches loaded renderer modules, prevents stale asynchronous
  renders from winning, and falls back safely after an optional module fails.
- The CLI handles help and argument errors before reading and compiling Wasm,
  and `--no-shadow` now disables text shadows as advertised.
- The package build runs `wasm-opt -Oz` before committing the generated Wasm.
- The benchmark covers pathological healer scaling, prepared options, prepared
  registries and themes, uniform and skewed tables, ANSI throughput, table
  memory growth, and base-versus-plugin callback costs.

## Remaining opportunities

The residual work requires a deliberate API or renderer design rather than a
local cleanup.

- **Medium — batched plugins.** A separate API could collect syntax or heading
  inputs, invoke JavaScript once, validate a result array, and then format with
  those results. It must define ordering, fallback, exception, and stateful
  callback semantics before replacing the current per-node adapters.
- **Low — table peak memory.** The two-pass renderer no longer retains styled
  cell strings, but Comrak's arena, the width vector, and the complete output
  still coexist. A material reduction would require a streaming formatter or a
  different parsing architecture.
